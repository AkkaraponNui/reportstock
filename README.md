# reportstock

ระบบวิจัยหุ้นต่างประเทศสำหรับการลงทุนระยะ 5 ปี ประกอบด้วยเครื่องมือ Python ที่ดึงข้อมูลและคำนวณแบบตรวจสอบย้อนกลับได้
และ sub-agent สี่ตัวใน Claude Code ที่ทำหน้าที่อ่านและวิเคราะห์

แนวคิดหลักคือแยก "ข้อเท็จจริง" ออกจาก "ความเห็น" คนละไฟล์ ตัวเลขทุกตัวในบทวิเคราะห์ต้องย้อนกลับไปหาแหล่งที่มาได้เสมอ

## เริ่มใช้งาน

```bash
uv sync
export REPORTSTOCK_UA="ชื่อคุณ you@example.com"   # จำเป็นสำหรับดึงเอกสาร SEC
uv run python -m streamlit run app.py
```

เปิดเบราว์เซอร์ที่ http://localhost:8501 แล้วใช้งานได้เลย ไม่ต้องพิมพ์คำสั่งอะไรอีก

ใช้ `python -m streamlit` ไม่ใช่ `streamlit` เฉยๆ เพราะ Windows Application Control
บล็อกไฟล์ streamlit.exe บนเครื่องนี้ การเรียกผ่านโมดูลเป็นทางเลี่ยงที่ใช้ได้

## หน้าจอในแอป

| หน้า | ใช้ทำอะไร |
|---|---|
| คุยกับนักวิเคราะห์ | ช่องแชทที่ตัวแทนอ่านข้อมูลจริงในเครื่องก่อนตอบ ไม่ตอบตัวเลขจากความจำ ต้องมีกุญแจ API |
| ค้นหาหุ้น | ค้นบริษัทไหนก็ได้บนโลก พิมพ์ชื่อบริษัทหรือสัญลักษณ์ กดปุ่มเดียวเพื่อดึงข้อมูลเข้าระบบ |
| รายงานหุ้นรายตัว | ตอนนี้เติบโตเท่าไหร่ กราฟงบย้อนหลัง คะแนน 5 เสา ภาพ 5 ปี ข่าว และความเสี่ยงที่บริษัทระบุเอง |
| กองทุนและ ETF | จัดอันดับกองทุนด้วยเกณฑ์ของกองทุนเอง และบอกว่าซื้อแล้วซ้ำกับหุ้นที่ถืออยู่แค่ไหน |
| โมเดลพยากรณ์การเติบโต | เส้นการชะลอตัวที่ประมาณจากข้อมูลจริง จำลองหลายพันรอบ และจัดอันดับสมมติฐานที่มีผลมากสุด |
| จัดอันดับ | เทียบหุ้นทุกตัวที่มีข้อมูลด้วยไม้บรรทัดเดียวกัน พร้อมกราฟเติบโตเทียบความถูกแพง |
| ภาพรวมมหภาค | ข่าวดอกเบี้ย เงินเฟ้อ นโยบายการค้า ที่กระทบทั้งพอร์ต |
| รายงานที่สร้างไว้ | อ่านและดาวน์โหลดรายงานที่เครื่องมือหรือ agent เขียนไว้ |

แอปกับ agent ใช้ไฟล์ชุดเดียวกัน ดึงข้อมูลจากหน้าเว็บแล้ว agent เห็นทันที และในทางกลับกันก็เช่นกัน
ไม่มีฐานข้อมูลแยก ไม่มีตรรกะสองชุด

## ครอบคลุมหุ้นทั่วโลก

ระบบวิเคราะห์ได้ทุกหุ้นที่ Yahoo Finance มีข้อมูล ไม่ได้จำกัดแค่รายชื่อใน `config/universe.yaml`
ไฟล์นั้นเป็นแค่ทางลัดสำหรับหุ้นที่ติดตามประจำ

```bash
uv run python tools/search_tickers.py "Toyota"          # ค้นจากชื่อบริษัท
uv run python tools/search_tickers.py "PTT" --limit 5   # หุ้นไทยก็ได้
```

รหัสตลาดต่อท้ายตามรูปแบบของ Yahoo `.BK` ไทย `.T` โตเกียว `.HK` ฮ่องกง `.KS` เกาหลี
`.L` ลอนดอน `.SW` ซูริก `.AS` อัมสเตอร์ดัม `.NS` อินเดีย `.TO` โตรอนโต `.AX` ออสเตรเลีย

บริษัทเดียวกันมักจดหลายตลาดและไม่เท่ากัน ตลาดบ้านเกิดสภาพคล่องดีกว่าและรายงานงบเป็นสกุลเงินตัวเอง
ส่วน ADR ในสหรัฐซื้อขายเป็นดอลลาร์แต่รายงานงบเป็นสกุลเงินบ้านเกิด ระบบตรวจจับและแจ้งเตือนกรณีนี้ให้

## ใช้ผ่านบรรทัดคำสั่ง

ทดลองรันหุ้นตัวเดียวให้ครบวงจร

```bash
uv run python tools/fetch_fundamentals.py NVDA
uv run python tools/fetch_news.py NVDA --days 90
uv run python tools/fetch_filings.py NVDA --risk-factors

```

ผลลัพธ์อยู่ใน `data/reports/<วันที่>-nvda-datapack.md`

## วิธีใช้ผ่าน agent

พิมพ์ในหน้า Claude Code ว่าต้องการวิเคราะห์อะไร แล้วเรียก skill ชื่อ `stock-research`
ระบบจะสั่ง agent ตามลำดับให้เอง ตัวอย่างคำสั่งที่ใช้ได้จริง

- วิเคราะห์ NVDA สำหรับถือ 5 ปี
- เทียบหุ้นกลุ่ม ai_infra ว่าตัวไหนน่าถือที่สุด
- สแกนทั้ง watchlist แล้วจัดอันดับ
- อัปเดตบทวิเคราะห์เดิม บอกเฉพาะสิ่งที่เปลี่ยนไป

## agent ทั้งสี่ตัว

| agent | หน้าที่ |
|---|---|
| `stock-data-collector` | ดึงงบการเงินและเอกสาร แล้วรายงานว่าข้อมูลส่วนไหนขาด ไม่ปล่อยให้วิเคราะห์บนช่องว่าง |
| `news-scout` | เก็บข่าวและบทความ แล้วคัดว่าอันไหนกระทบกำไรระยะยาวจริง อันไหนแค่ทำให้ราคาขยับวันนี้ |
| `macro-analyst` | ดูดอกเบี้ย นโยบายการค้า วัฏจักรการลงทุน แล้วโยงว่ากระทบหุ้นตัวไหนผ่านกลไกอะไร |
| `equity-analyst` | เขียนบทวิเคราะห์ 5 ปี พร้อมเหตุผลฝั่งบวกและฝั่งลบอย่างละเอียด |

`news-scout` คือตัวที่คัดข่าวตามที่ออกแบบไว้ หัวใจของมันคือคำถามเดียว ข่าวนี้เปลี่ยนความสามารถในการทำกำไรอีกห้าปีข้างหน้า
หรือเปลี่ยนแค่ราคาพรุ่งนี้ ข่าวประเภทหลังถูกนับแล้วทิ้ง ไม่เข้าไปในรายงาน

## โมเดลให้คะแนน

คะแนนรวม 0-100 ถ่วงน้ำหนักจากห้าเสา

| เสา | น้ำหนัก | ดูอะไร |
|---|---:|---|
| Growth | 30% | CAGR รายได้ การเติบโต TTM กำไรสุทธิ ประมาณการข้างหน้า |
| Quality | 25% | ROIC มาร์จิ้นและทิศทางของมาร์จิ้น ROE |
| Cash | 15% | FCF margin การเติบโตของ FCF และ FCF yield |
| Balance sheet | 15% | หนี้สุทธิต่อ EBITDA D/E current ratio |
| Valuation | 15% | forward P/E PEG EV/EBITDA P/S |

ถ้า metric ไหนไม่มีข้อมูล ระบบจะถ่วงน้ำหนักใหม่เฉพาะตัวที่มี และรายงาน coverage ให้เห็นว่าคะแนนนั้นตั้งอยู่บนข้อมูลกี่เปอร์เซ็นต์

ส่วนฉายภาพ 5 ปีทำงานแบบ fade model อัตราเติบโตปัจจุบันค่อยๆ ลดลงสู่อัตราปลายทาง มาร์จิ้นเคลื่อนตามเทรนด์ของตัวเอง
แล้วตีมูลค่าด้วย exit multiple ที่ผสมระหว่าง forward P/E วันนี้กับตัวคูณที่สมเหตุสมผลกับการเติบโตปลายทาง

ตัวเลขที่ได้เป็นผลทางคณิตศาสตร์ของสมมติฐานที่พิมพ์กำกับไว้ ไม่ใช่การพยากรณ์ราคา เปลี่ยนสมมติฐานตัวเลขก็เปลี่ยน
ค่านี้มีไว้เทียบหุ้นด้วยไม้บรรทัดอันเดียวกัน ไม่ได้มีไว้ทำนาย

## โมเดลพยากรณ์การเติบโต

หน้าโมเดลทำสามอย่างที่ต่างจากหน้าคะแนน

**ประมาณเส้นชะลอตัวจากข้อมูลจริง** แทนที่จะใช้เส้นตรงที่กำหนดเอง ระบบประมาณสมการ
`การเติบโตปีหน้า = a + b × การเติบโตปีนี้` จากทุกบริษัทที่มีข้อมูลในเครื่อง
แล้วรายงานจำนวนข้อมูลและ R-squared ให้เห็นว่าเส้นนั้นเชื่อได้แค่ไหน

ในชุดข้อมูลเล็ก จุดที่โตผิดปกติไม่กี่จุดจะดึงเส้นถดถอยเข้าหาตัวเองและดัน R-squared ให้สูงเกินจริง
ระบบจึงประมาณสองครั้ง ครั้งหนึ่งใช้ทุกจุด อีกครั้งตัดปีที่โตเกิน 50% ออก แล้วใช้เวอร์ชันที่ไม่ได้ถูกจุดไม่กี่จุดควบคุม
ส่วนความต่างระหว่างสองเส้นถูกนับเป็นความไม่แน่นอนเพิ่มเข้าไปในการจำลอง

**จำลอง Monte Carlo** สุ่มอัตราการเติบโต มาร์จิ้น และตัวคูณตอนขายหลายพันรอบ
แล้วรายงานช่วงผลลัพธ์แทนตัวเลขเดียว พร้อมสัดส่วนของรอบที่ขาดทุนและที่ชนะเกณฑ์ต่างๆ

**วิเคราะห์ความอ่อนไหว** ขยับสมมติฐานทีละตัวแล้ววัดว่าค่ากลางเปลี่ยนไปเท่าไหร่
ลำดับสำคัญกว่าขนาด เพราะมันบอกว่าควรไปตรวจสอบตัวเลขไหนก่อนเชื่อผลลัพธ์
โดยทั่วไปตัวคูณตอนขายมีผลมากที่สุด ซึ่งบังเอิญเป็นสิ่งที่ไม่มีใครพยากรณ์ได้

**เขียนรายงานให้ทุกครั้งที่รัน** ทั้งจากบรรทัดคำสั่งและจากหน้าแอป ไฟล์ไปอยู่ที่
`data/reports/<วันที่>-<ชื่อ>-prediction.md` อ่านและดาวน์โหลดได้จากในแอป

รายงานขึ้นต้นด้วยคำตอบ ตามด้วยว่าควรเชื่อได้แค่ไหน แล้วจึงเป็นตารางช่วงผลตอบแทน ฮิสโตแกรมแบบข้อความ
อันดับสมมติฐานที่เป็นตัวตัดสิน สมมติฐานทั้งหมดที่ใช้ สถิติของเส้นที่ประมาณได้ และข้อจำกัด

ถ้ารันหลายตัวพร้อมกัน จะได้รายงานเปรียบเทียบแทน ซึ่งจัดอันดับให้ ชี้ว่าตัวไหนช่วงกว้างที่สุด
และเตือนเรื่องความกระจุกตัวเมื่อหุ้นหลายตัวอยู่กลุ่มเดียวกัน

```bash
uv run python tools/predict.py NVDA                          # รายงานตัวเดียว
uv run python tools/predict.py ai_infra --report-name ai      # รายงานเปรียบเทียบ
uv run python tools/predict.py NVDA --no-report               # เอาแต่ JSON
```

ข้อจำกัดที่ต้องพูดให้ชัด โมเดลนี้ไม่เคยถูกตรวจสอบกับผลลัพธ์จริงนอกชุดข้อมูล
เพราะ Yahoo Finance ให้ข้อมูลปัจจุบันโดยไม่มีประวัติแบบ point-in-time การทำ backtest อย่างซื่อสัตย์จึงเป็นไปไม่ได้
ช่วงตัวเลขที่เห็นคือช่วงของสมมติฐาน ไม่ใช่ความน่าจะเป็นของสิ่งที่จะเกิดขึ้นจริง

## ช่องแชท

ตัวแทนมีเครื่องมืออ่านข้อมูลในเครื่อง 16 ตัว ครอบคลุมงบการเงิน คะแนน ผลโมเดลจำลอง ข่าว กองทุน
เอกสารความเสี่ยงจาก SEC รายงานที่เคยสร้างไว้ การค้นหาหุ้นทั่วโลก และการดึงข้อมูลหุ้นใหม่

กฎสำคัญที่เขียนไว้ใน system prompt คือห้ามตอบตัวเลขจากความจำ ต้องอ่านไฟล์ก่อนเสมอ
ถ้าความรู้ของโมเดลขัดกับไฟล์ ให้เชื่อไฟล์และบอกวันที่ของ snapshot

ต้องตั้งค่ากุญแจ API ก่อนใช้ หน้าอื่นทั้งหมดทำงานได้โดยไม่ต้องใช้กุญแจ

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
```

ใช้โมเดล `claude-opus-5` และคิดค่าใช้จ่ายตามปริมาณการใช้งาน ปรับความละเอียดในการคิดได้จากแถบด้านข้าง
ระดับต่ำตอบเร็วและถูกกว่า ระดับสูงคิดละเอียดกว่า

## กองทุนและ ETF

กองทุนไม่ใช่บริษัท มันไม่มีงบกำไรขาดทุน จึงไม่มีรายได้ มาร์จิ้น หรือ ROIC ให้วัด
การยัดกองทุนเข้าเกณฑ์ห้าเสาของหุ้นจะได้ผลลัพธ์ว่างหรือไม่ก็ไร้ความหมาย ระบบจึงใช้เกณฑ์คนละชุด

## ข้อจำกัดที่ต้องรู้

Yahoo Finance เป็นข้อมูลดีเลย์และมีการแก้ย้อนหลัง เพียงพอสำหรับเทียบโครงสร้างระยะปี แต่ไม่เหมาะกับอะไรที่อ่อนไหวต่อเวลา

หุ้นที่ไม่ได้จดทะเบียนในสหรัฐ เช่น `7203.T` `0700.HK` `NESN.SW` `005930.KS` ไม่มีเอกสารใน SEC
หลักฐานฝั่งความเสี่ยงจึงไม่เท่ากันระหว่างหุ้นอเมริกากับหุ้นประเทศอื่น

`roic_est` ใช้อัตราภาษีคงที่ 21% ไม่ใช่อัตราจริงของแต่ละบริษัท ใช้จัดอันดับได้ แต่ไม่ใช่ค่าที่แม่นยำ

หุ้นกลุ่มธนาคารและประกันทำให้อัตราส่วนหลายตัวไม่มีความหมาย หนี้สุทธิและ EV/EBITDA ของธนาคารเทียบกับหุ้นอุตสาหกรรมไม่ได้

การติดแท็กข่าวใช้การจับคำ ผิดพลาดได้เป็นปกติ เป็นแค่ตัวกรองชั้นแรก ไม่ใช่คำตัดสิน

ที่สำคัญที่สุด โมเดลอ่านอดีตแล้วสมมติว่ารูปแบบเดิมดำเนินต่อ มันมองไม่เห็นธุรกิจที่กำลังเปลี่ยนรูป
ซึ่งในช่วงห้าปีมักเป็นสิ่งที่ตัดสินผลลัพธ์จริงๆ คะแนนสูงจึงเป็นเหตุผลให้ไปดูให้ละเอียด ไม่ใช่ข้อสรุป

## โครงสร้างไฟล์ผลลัพธ์

```text
data/raw/<TICKER>/<วันที่>.json          งบการเงินและ metric
data/news/<TICKER>/<วันที่>.json         ข่าวที่เก็บได้ พร้อมแท็ก
data/news/<TICKER>/brief-<วันที่>.md     บทคัดกรองข่าวจาก news-scout
data/news/_macro/<วันที่>.json           ข่าวมหภาค
data/filings/<TICKER>/<วันที่>.json      เอกสาร SEC และเนื้อหา Risk Factors
data/scores/<TICKER>/<วันที่>.json       คะแนนรายเสาและฉากทัศน์
data/reports/<วันที่>-<ชื่อ>-datapack.md   ข้อเท็จจริงล้วน ไม่มีความเห็น
data/reports/<วันที่>-macro-brief.md      บทวิเคราะห์มหภาค
data/reports/<วันที่>-<ชื่อ>-thesis.md     บทวิเคราะห์การลงทุน
```

snapshot ลงวันที่ไว้และไม่เขียนทับข้ามวันโดยตั้งใจ เพื่อให้ย้อนกลับไปตรวจได้ว่าข้อสรุปในอดีตสมเหตุสมผลกับข้อมูลที่มีอยู่ ณ เวลานั้นหรือไม่

## นำขึ้นออนไลน์

deploy ได้ และมีตัวเลือกฟรีหลายทาง อ่านรายละเอียดใน [DEPLOY.md](DEPLOY.md)

สรุปสั้น ระบบกินหน่วยความจำสูงสุดราว 147 MB จึงอยู่ในโควตาฟรีของทุกแพลตฟอร์มสบายๆ
แต่มีสองเรื่องที่ต้องรู้ก่อน Yahoo Finance มักจำกัดหรือบล็อก IP ของศูนย์ข้อมูล
และแพลตฟอร์มฟรีใช้ระบบไฟล์ชั่วคราว ข้อมูลใน `data/` จะหายทุกครั้งที่แอปรีสตาร์ท

ถ้าต้องการให้ข้อมูลไม่หายและดึงข้อมูลได้เสถียร วิธีที่ดีที่สุดคือรันบนเครื่องตัวเองแล้วเปิดผ่าน Cloudflare Tunnel

เมื่อ deploy ขึ้นที่สาธารณะ ให้ตั้งตัวแปร `APP_PASSWORD` ระบบจะเปิดหน้าใส่รหัสผ่านให้อัตโนมัติ
ถ้าไม่ตั้ง จะไม่มีการถามรหัส ซึ่งเหมาะกับการใช้บนเครื่องตัวเอง

## ข้อความกำกับ

ระบบนี้เป็นเครื่องมือวิจัย ไม่ใช่คำแนะนำการลงทุน ไม่ส่งคำสั่งซื้อขาย และไม่รับประกันความถูกต้องของข้อมูลจากแหล่งภายนอก
การตัดสินใจลงทุนและความเสี่ยงทั้งหมดเป็นของผู้ใช้
